# 히스토리 화면 설계

날짜: 2026-08-11

## 목표

토큰 사용 내역을 구체적으로 볼 수 있는 화면을 만든다. 세 가지를 본다.

1. 세션별 목록과 드릴다운
2. 시간축 추이 그래프
3. 일·주 단위 비교

기존 미터 창을 토글로 확장해서 그 안에 넣는다. 별도 창을 띄우지 않는다.

## 지금 있는 것

- `state.json` — 세션 57개(프로젝트·모델·시작/마지막 시각·토큰·비용), 일별 합계(`days`, 60일 보관), 프로젝트/모델/벤더/엔드포인트/서비스/플랜별 집계
- `tp status` — 위 내용을 터미널 표로 전부 출력
- 오버레이 패널 3종 — `sessions`(8줄) / `board`(5줄) / `days`(7줄), 더블클릭으로 순환

## 없는 것

- 시간축 세밀도. 집계만 저장하므로 "오늘 몇 시에 얼마나 썼나"를 복원할 수 없다.
- 저장된 세션 57개를 넉넉히 훑을 화면. 축소 미터는 8줄까지만 보인다.

## 결정

| 항목 | 결정 |
|---|---|
| 시계열 해상도 | 1시간 버킷 × 프로젝트별 |
| 화면 | 미터 창 토글 확장 (별도 창 아님) |
| 레이아웃 | 상단 그래프 고정 + 하단 목록(기존 패널 전환 재사용) |
| 세션 열린 시각 | 확장 모드에만 표시, `MM-DD HH:MM` |
| 세션 정렬 | 현행 유지 (tok/s 내림차순 → `last_seen` 내림차순) |

## 1. 데이터 레이어 — 시간 버킷

### 제약

`Meter.ingest()`는 델타마다 `state.json` 전체를 rewrite한다(`meter.py:288`). 현재 파일 53KB, 하루 약 7,600회 호출. 60일치 시간 버킷(1,440시간 × 프로젝트 12개)을 이 파일에 넣으면 ~1MB가 되고 매 호출 쓰기 비용이 20배가 된다. 그래서 별도 파일로 뺀다.

### 방식

`_roll_today()`(`meter.py:243`)와 같은 리듬을 시간 단위로 적용한다.

- 진행 중인 1시간 버킷만 `state["hour"]`에 둔다. 프로젝트 12개 × 숫자 3개라 파일 증가분은 무시할 수준이다. 구조는 jsonl 한 줄과 동일하게 `{"h": "2026-08-11T15", "p": {...}}`로 두고, `_default_state()`에 빈 값으로 추가한다.
- 시간이 넘어가면 `data/hours.jsonl`에 한 줄 append하고 `state["hour"]`를 비운다. 디스크 append는 시간당 1회.
- 데몬이 죽어도 진행 중 버킷은 `state.json`에 남아 있으므로 유실되지 않는다.

`ingest()`에 `_roll_hour()` 호출 한 줄을 `_roll_today()` 옆에 추가하고, 프로젝트 누적 한 줄을 기존 `touched` 루프 뒤에 붙인다.

### 파일 형식

`data/hours.jsonl`, 한 줄이 한 시간:

```json
{"h":"2026-08-11T15","p":{"api-server":[1234567,12.34,88],"tokenmeter":[4321,0.12,3]}}
```

값은 `[토큰합, 비용USD, 호출수]`. 토큰합은 `tokens_of()`와 같은 정의(입력+캐시읽기+캐시쓰기+출력)를 쓴다.

키를 한 글자로 줄인 이유는 이 파일이 하루 24줄씩 무기한 늘어나기 때문이다.

### 보관

`HOURS_KEPT = 24 * 60` (60일, `DAYS_KEPT`와 맞춘다). 초과분은 앞줄부터 잘라낸다. 자르기는 파일 rewrite라 하루 1회, 날짜가 바뀔 때만 수행한다.

## 2. 읽기 레이어 — `tokenmeter/history.py` (신규)

Qt를 import하지 않는다. 순수 함수만 둔다. `overlay.py`는 이미 45KB이므로 집계 로직을 그쪽에 붙이지 않는다.

레이어상 `meter.py`(인프라: 상태 파일 입출력)와 `overlay.py`(프레젠테이션) 사이의 애플리케이션 계층이다.

```python
def load_hours(state: dict) -> list[tuple[str, dict[str, list]]]:
    """hours.jsonl + 진행 중 state["hour"] 를 시간순으로 합쳐 돌려준다.
    mtime 이 그대로면 파싱 결과를 재사용한다 (오버레이가 200ms 마다 부른다).
    깨진 줄은 조용히 건너뛴다."""

def series(hours, span: str, project: str | None = None) -> Series:
    """span: "today"(24점) | "7d"(일별 7점) | "30d"(일별 30점).
    project 를 주면 그 프로젝트만. 각 점은 (라벨, 프로젝트별 값 dict, 합계)."""
```

`Series`는 막대 하나당 `(x비율, 높이비율, 프로젝트별 구간)`까지 계산해서 넘긴다. `overlay.py`는 좌표를 받아 칠하기만 한다.

## 3. 화면 — 미터 창 확장 모드

### 상태

`MeterWindow.expanded: bool`. `_store_prefs()`(`overlay.py:312`)에 항목을 추가해 `overlay.json`에 저장한다. 그래프 범위(`today`/`7d`/`30d`)도 같이 저장한다.

토글은 **우클릭 메뉴 항목 + 미터 우상단 `⤢` 버튼**. 더블클릭은 이미 패널 순환(`_cycle_panel`)에 배정돼 있어 건드리지 않는다.

### 크기

`_size()`(`overlay.py:298`)에 확장 분기를 넣는다.

- 폭: `BASE_W * 2.2` (340 → 750)
- 높이: 기존 계산 + `GRAPH_H` + 목록 줄 수를 `PANEL_ROWS`의 2배로

축소로 돌아오면 원래 크기와 위치를 복원한다. 화면 밖으로 나가지 않게 기존 `visible_pos` 로직을 통과시킨다.

### 그래프

QPainter 스택 막대. 새 의존성 없음(프로젝트 원칙).

- 프로젝트 색은 이름 해시 → HSL. 팔레트를 손으로 관리하지 않는다.
- 범위 토글 `[오늘] [7일] [30일]`을 그래프 우상단에 두고 클릭 영역으로 처리한다.
- 데이터가 비면 "하루가 지나면 쌓입니다" 류의 안내를 그린다(`_day_rows`의 기존 문구 방식과 동일).

### 세션 줄의 시각 칸

확장 모드에서만 `SESSION_COLS`에 칸 하나를 앞에 추가한다. 축소 모드의 5칸 배치는 그대로 둔다 — 폭 340px에서 이미 빠듯하다(`overlay.py:70` 주석).

형식은 `MM-DD HH:MM`, 출처는 세션 레코드의 `started_at`. 오늘 세션이라고 날짜를 생략하지 않는다. 표기가 일정해야 눈이 헷갈리지 않는다.

정렬은 바꾸지 않는다. 축소 미터의 존재 이유가 "지금 누가 태우고 있나"이므로 tok/s 우선을 유지한다.

## 4. 드릴다운

저장한 데이터 안에서만 한다.

- **세션 행 클릭** — 그래프가 그 세션의 *프로젝트*로 필터되고, 하단 목록이 그 세션 상세(입력/출력/캐시읽기/캐시쓰기/모델/시작~마지막/호출수)로 바뀐다.
- **일별 행 클릭** — 그래프가 그 날짜의 24시간으로 바뀐다.
- **ESC 또는 같은 행 재클릭** — 해제.

세션 내부의 분 단위 곡선은 제공하지 않는다. 버킷에 세션 차원을 추가해야 하는데 파일이 세션 수만큼 커진다. 필요해지면 그때 넣는다.

## 5. 검증

- `test_tokenmeter.py::test_hour_rollover` — 시간이 넘어가면 `hours.jsonl`에 append되고 `state["hour"]`가 비는지, `HOURS_KEPT` 초과분이 잘리는지, 데몬 재시작 후 진행 중 버킷이 이어지는지.
- `history.py::demo()` — assert 기반 self-check. `series()`의 span별 점 개수, 프로젝트 필터, 빈 파일, 깨진 줄 무시.
- `overlay.py::_demo()` — 기존 패턴대로 확장/축소 크기 계산과 그래프 좌표, 확장 모드 세션 줄의 시각 칸을 assert.

## 하지 않는 것

- 세션 단위 시계열 (파일 크기)
- 호출 하나하나의 raw 로그 (원천 JSONL 재파싱 필요, 저장량 큼)
- 별도 히스토리 창 (미터 확장으로 대체)
- 그래프 라이브러리 추가 (QPainter로 충분)
- 축소 미터의 칸 배치 변경
